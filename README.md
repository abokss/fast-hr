# FastHR 1.0

Локальное приложение для первичного отбора: **вакансия → много PDF → анализ → рейтинг → ручной shortlist**.

## Запуск

1. Запустите Docker Desktop.
2. Дважды нажмите **Start FastHR.command** в папке проекта.
3. Откройте **http://127.0.0.1:8501**. Окно запуска должно оставаться открытым.

Запуск поднимает PostgreSQL, применяет миграции и запускает FastAPI + Streamlit.
Если порт 8000 или 8501 уже занят предыдущим запуском, сначала остановите его.
Ctrl+C в окне запуска останавливает приложение; база продолжает работать.

### Первичная установка на другом компьютере

Python 3.9+ (проверено на 3.9), Docker Desktop / Docker Compose:

```sh
python3 -m venv backend/venv
source backend/venv/bin/activate
python -m pip install -r backend/requirements-dev.txt -r frontend/requirements.txt
cp .env.example .env
python scripts/run_local.py
```

Не перезаписывайте существующий `.env`. Пример содержит только локальные настройки разработки.
Изменение `POSTGRES_*` не меняет пароль уже существующей базы. Данные хранятся в Docker volume;
не удаляйте его для исправления подключения. `DATABASE_URL` должен соответствовать данным PostgreSQL.
Переменные окружения имеют приоритет над `.env`.

Ручной запуск:

```sh
docker compose up -d --wait db
cd backend
venv/bin/python -m alembic upgrade head
venv/bin/python -m uvicorn app.main:app --host 127.0.0.1 --port 8000
```

В другом терминале, из корня проекта:

```sh
backend/venv/bin/python -m streamlit run frontend/streamlit_app.py --server.address 127.0.0.1 --browser.gatherUsageStats false
```

## Использование

1. Создайте вакансию: название, описание, список требуемых навыков через запятую.
2. Выберите вакансию слева, загрузите PDF (до 100 за раз, до 200 на вакансию).
3. Нажмите «Рассчитать рейтинг».
4. Откройте кандидата: контакты, совпадения, отсутствующие упоминания, фрагменты опыта/образования/проектов и оригинал PDF.
5. Добавьте выбранных кандидатов в shortlist и скачайте таблицу CSV.

Файл: до 10 МБ, 30 страниц, 200 000 символов. Повреждённые, зашифрованные PDF и сканы без текстового слоя отклоняются с объяснением; остальные файлы пакета сохраняются.
Повторный файл в одной вакансии обнаруживается по SHA-256.

## Как считается рейтинг

- Один `TfidfVectorizer` обучается на описании вакансии и **всех** резюме одного запуска.
- Применяются Unicode-нормализация, приведение регистра, выделение технических токенов и sublinear TF.
- Cosine similarity сравнивает каждый CV с вакансией. В интерфейсе показано `cosine × 100`.
- Навыки сопоставляются по явному словарю синонимов и границам слов; произвольные навыки ищутся как точные фразы без учёта регистра.
- **Match = 100 × число найденных требуемых навыков / число требуемых навыков**.
- Сортировка: Match по убыванию, затем cosine по убыванию, затем ID по возрастанию.
- Если навыки не заданы, Match равен cosine × 100.
- Все навыки имеют одинаковый вес. Отдельных весов за опыт, образование и персональные сведения нет; TF-IDF сравнивает полный извлечённый текст.
- Добавление новых CV сбрасывает старые оценки: необходимо пересчитать общий корпус. Shortlist сохраняется.

Это лексическое сходство и совпадение упоминаний, не семантическое понимание и не вероятность успешного найма.
Упоминание навыка не доказывает владение им: отрицания и контекст не интерпретируются.
Имена и телефоны извлекаются эвристически; имя явно отмечено как предположение. Разделы опыта и образования — исходные фрагменты, не выдуманная оценка стажа.
Английские и русские заголовки поддержаны простыми правилами, OCR отсутствует. Решение о shortlist принимает человек.

Метод TF-IDF: https://scikit-learn.org/stable/modules/feature_extraction.html#text-feature-extraction

## Хранение и структура

PostgreSQL: прежняя `candidates`, новые `vacancies`, `resumes`, `match_results`.
Резюме принадлежит вакансии; отсутствие email не мешает загрузке. `candidate_id` пока необязателен:
автоматического слияния разных CV в одну личность нет. Повторное резюме в другой вакансии допустимо.

Оригиналы — в `data/resumes/` с внутренними UUID-именами; текст и результаты — в БД.
`STORAGE_DIR` переопределяет каталог файлов, `FASTHR_API_URL` — адрес backend для UI.
`.env`, резюме и локальные данные исключены из Git. Резервируйте и БД, и каталог `data/` вместе.

```text
backend/app/
  main.py, config.py, database.py, models.py, schemas.py
  routers/        HTTP API
  services/       импорт PDF, разбор и обработка анализа
  nlp/            словарь навыков, TF-IDF и оценки
backend/migrations/   Alembic; сохраняет существующую candidates
backend/tests/        API, алгоритмы, пакет из 100 синтетических PDF
frontend/             Streamlit
scripts/run_local.py  запуск приложения
```

Основные API: `POST/GET /vacancies`, `POST/GET /vacancies/{id}/resumes`,
`POST /vacancies/{id}/analyze`, `GET /vacancies/{id}/ranking`,
`GET /vacancies/{id}/resumes/{resume_id}`, `PATCH .../shortlist`, `GET .../file`.
Старые `/candidates` и `/resumes/upload` сохранены. Документация: http://127.0.0.1:8000/docs.

## Проверки

```sh
cd backend
PYTHONDONTWRITEBYTECODE=1 venv/bin/python -m unittest discover -s tests -v
```

Автотесты изолированы от рабочей БД (SQLite + моделирование ошибок PostgreSQL).
Пакетный тест содержит 100 коротких синтетических PDF: он не является гарантией скорости для любых реальных файлов.
Для проверки PostgreSQL нужен отдельный интеграционный прогон.

## Границы версии

Это локальная однопользовательская V1, без авторизации и публичного развёртывания.
API и UI по умолчанию слушают только 127.0.0.1. Не публикуйте их в интернете без контроля доступа.
Большие задания выполняются в потоке сервера; фоновые очереди пока не добавлены.
Редактирование/удаление вакансий, OCR, глубокое понимание опыта, восстановление потерянных PDF и multi-user режим — последующие улучшения.
Тесты кандидатов, AI-интервью и прокторинг (FastHR 2.0–4.0) не реализованы.
